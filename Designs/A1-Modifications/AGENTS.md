# Reglas de A1-Modifications

Estas instrucciones se aplican a esta carpeta y a todas sus subcarpetas.

## Renders

- Mostrar la geometría real del modelo final. No inventar piezas ni modificar la geometría para la imagen.
- Usar siempre el modelo de color plomo/gris neutro, con fondo gris oscuro opaco y cuadrícula discreta, como una vista de Bambu Studio.
- Mantener iluminación suave y encuadre completo, sin recortes, interfaz, textos, colores de filamento ni fondos transparentes.
- Guardar una sola vista útil como `Preview.png`, optimizada y de tamaño moderado: aproximadamente 800 × 600 px y preferentemente menos de 250 KB.
- No añadir capturas de referencia, escenas de Blender ni renders duplicados al repositorio.

## Índices y fichas

- Todo README de una carpeta que agrupe modelos, como `Cable-Chains`, debe tener una tabla con miniatura, nombre enlazado y una descripción breve.
- La miniatura también debe enlazar a la carpeta del modelo. Usar `<img src="Modelo/Preview.png" width="240" alt="Descripción">` dentro del enlace, sin imágenes gigantes.
- Reutilizar la misma imagen en los índices y en la ficha; no crear copias para cada tabla.
- Las fichas deben ser breves: descripción, modelo final para descargar, render y enlace directo a la fuente original, con autor y licencia en una línea.
- Conservar únicamente las notas necesarias para usar o imprimir el modelo, por ejemplo una pausa de impresión o un perfil de otra impresora.
- Verificar la fuente original; no inventar URLs ni presentar una búsqueda como el enlace del modelo.

## Nombres y espacio en GitHub

- Usar `Bed-Dragchain` y `Side-Dragchain`, sin sufijos `2026`, `V2` o números de revisión en sus carpetas, títulos o archivos finales.
- Guardar solamente el proyecto final necesario en `Files/`. Si el conjunto ya incluye todas las piezas, no guardar también piezas sueltas, STL exportados o formatos duplicados sin una petición expresa.
- No guardar originales anteriores, derivados intermedios, carpetas `Sources/`, copias de respaldo, registros de sustitución, informes de verificación, catálogos ni listas de hashes en esta categoría.
- La procedencia, autoría, licencia y cualquier cambio relevante se resumen en el README; no duplicarlas en `Attribution.md` u otros registros.
- Git conserva el historial. No duplicar archivos para registrar versiones ni reescribir o purgar el historial remoto sin una petición expresa.
- Guardar scripts temporales, pruebas y archivos de trabajo fuera de esta categoría y fuera de los cambios publicados.
- Al mover, renombrar o retirar modelos, actualizar todos los enlaces e índices afectados y comprobar que no queden rutas rotas.
